01 / PROJECT OVERVIEW

Two perspectives on the same city

CityPulse combines current weather from the Open-Meteo Forecast API with nearby monitoring-station readings from OpenAQ API v3. A user can select a popular-city example or search by city name; geocoding returns coordinates that the app uses to fetch the weather and the closest available air-quality station.

This pairing adds everyday context, but the two sources may represent different places and reporting times. Particulate matter (PM) values are measured concentrations, not AQI values.

The frontend uses Fetch API with async/await to call same-origin backend routes. The backend keeps the OpenAQ API key private and calls its MCP tool over stdio. This demonstrates MCP in a Node service where the app backend and MCP subprocess run together.

03 / TECHNICAL DECISIONS

Implementation choices and failure handling

01

Vite + vanilla JavaScript

Multi-page UI without an unnecessary framework; native Fetch API keeps the asynchronous data flow explicit.

02

Express server-side API proxy

The browser never receives the API key. The backend validates query parameters and coordinates, applies request timeouts, maps upstream errors, and rate-limits API calls. Successful weather responses are cached for 10 minutes; the most recent response can be shown as a clearly labeled cached reading during a temporary provider outage.

03

Independent source states

If OpenAQ has no key, station, or response, available Open-Meteo weather remains visible with an explicit unavailable message. A weather API failure returns an actionable error instead of fabricated data.

04

MCP behind the backend

The MCP server exposes one typed tool to summarize normalized values. It accepts no SQL and makes no upstream requests; the backend connects through an MCP Client and stdio transport.

05

No invented AQI value

OpenAQ provides sensor concentrations rather than an AQI score. The UI shows units and data limitations instead of implying unsupported health guidance.

API

An HTTP contract for retrieving structured source data such as geocoding, forecasts, and sensor measurements.

MCP

A protocol that connects a model or client to tools. Here it exposes a tool that summarizes data already collected by the app.

Agent Skill

On-demand workflow instructions for an AI coding agent. It supports development and maintenance; it is not a data API or runtime service.

04 / OPERATIONS

Setup, testing, and deployment

  1. Copy .env.example to .env and set OPENAQ_API_KEY. Never put the key in frontend code.
  2. Run npm install, then npm run dev. Open the Vite URL; the backend listens on port 3001.
  3. Run npm test and npm run build before deployment.
  4. Deploy as a Node web service: build command npm ci --include=dev && npm run build, start command npm start, and configure OPENAQ_API_KEY as a host secret.

The Vite development proxy and production same-origin setup avoid browser CORS issues. Open-Meteo responses are cached in process memory to reduce repeat calls; a rate-limited response returns a retry hint, and a previous result may be served for up to six hours with a cached label. Render deployment is configured in render.yaml; other hosts must provide a Node.js 20–24 runtime and the environment variables described above. The rate limiter and response cache use in-memory state, suitable for a demo or single instance; multi-instance production should use shared stores. Confirm current OpenAQ key, quota, terms, and service availability before release.
